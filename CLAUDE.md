# CLAUDE.md — Real Life Games Enhancer

Компаньон для настоящих игр (дартс, шахматы, дурак, пинг-понг, «любая игра»): ведёт счёт и добавляет
roguelike-слой — **души** (валюта), **Алтарь Судеб** (колесо / пакт / сглаз / очищение), **дары и проклятия**
(перки, меняющие правила для конкретного игрока). Мрачный PS1-стиль: 3D-миры на Three.js с самописным ретро-рендером.
Владелец проекта — Арни. Интерфейс и тексты — на русском.

## Команды

```bash
npm install          # зависимости
npm run dev          # дев-сервер Vite (http://localhost:5173)
npm test             # vitest — логика игр и экономики (46+ тестов)
npm run typecheck    # tsc без эмита
npm run build        # tsc + vite build → dist/ (PWA, относительный base)
npm run preview      # раздать dist/ локально
node scripts/gen-icons.mjs   # перегенерировать PWA-иконки (пиксель-арт без внешних утилит)
```

Перед коммитом: `npm run typecheck && npm test && npm run build`.

## Правила, которые нельзя ломать

1. **Логика чистая.** `core/` и `games/*/logic.ts` не импортируют React, Three или audio. Мутации — только через
   `act((draft) => …)` из `core/store.ts` (immer + снимок для undo). Внутри логики — никаких `Math.random()`:
   только `nextRandom(session)` из `core/rng.ts`.
2. **Результат `act()` отвязывается от драфта** (JSON-клон) — можно возвращать объекты из мутаций.
3. **Визуал и звук — в UI-слое.** Доска игры вызывает `act(...)`, затем `fx({...})` и `sfx.xxx()`. В логике их нет.
4. **Доход считается по «сырым» очкам**, а не по очкам после перков — иначе экономика разгоняется.
5. **Новый перк** = объект `PerkDef` в `games/<id>/perks.ts` (или `core/perks/generic.ts`). Если перк меняет
   счёт автоматически — добавь `effect: { tag }` и обработай тег в логике игры. Тексты — живые, короткие, на «ты».
   Плейсхолдеры `{param}` требуют `params`. Тест `perk content` проверит id и параметры.
6. **Новая игра** — см. `docs/ARCHITECTURE.md` → «Как добавить игру». Порядок миров в хабе: `GAME_ORDER` (meta.ts)
   и `HUB_ORDER` (three/scenes/hub.ts) должны совпадать.
7. **PS1-стиль.** Все 3D-материалы — через `ps1({...})`. Текстуры маленькие (16–64px, мишень 256), фильтр Nearest.
   Больших плоскостей без сегментов не делай — аффинные UV «поплывут». Источников света в сцене ≤ 4.
8. **UI = те же пиксели, что и 3D.** Заголовки и числа — только через `PixelText`/пресеты `ui/pixel/Type.tsx`
   (растр + дизер), элементы управления — Tiny5 на размерах, кратных 8px, окна и кнопки — 9-slice рамки
   из `ui/pixel/theme.ts` (`--f-*`). Запрещено: blur, `backdrop-filter` для красоты, плавные градиенты, мягкие тени,
   «гладкий» DOM-заголовок. Подробно — `docs/ART_DIRECTION.md` §3.
9. **Без внешних ассетов**: картинки, звуки, модели — процедурные. Это держит сборку лёгкой и офлайн-готовой.
10. **3D-ввод.** Сцена не меняет стор: она шлёт `SceneEvent`, доска игры решает. На `scene.ready` доска обязана
   переслать состояние (сцена строится заново после алтаря/хаба). Текст в 3D — тексель ≈ пиксель при 240p.

## Баланс (коротко)

Цены: колесо 1, пакт 3, сглаз 2 (−1 против лидера), очищение 2. Слоты: 4 дара / 3 проклятия.
Отстающим меньше проклятий и больше редких даров; лидеру — наоборот. Два проклятия подряд → вращение без проклятий.
Хаос (Тихий омут / Сумерки / Безумие) масштабирует проклятия и легенды. Все числа — в `core/shrine.ts`;
обоснование — в `docs/GAME_DESIGN.md`. Меняешь числа — обнови тесты `src/__tests__/shrine.test.ts` и доку.

## Деплой

GitHub Actions (`.github/workflows/deploy.yml`) собирает и публикует `dist/` на GitHub Pages при пуше в `main`.
`base: './'` — сборка работает в любом подкаталоге и на любом статическом хостинге.
