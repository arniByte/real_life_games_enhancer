# Архитектура

## Слои

```
┌──────────────────────── UI (React) ────────────────────────┐
│ App · screens (Title/Hub/Setup/Play/Shrine/Results/Modals)  │
│ games/*/Board.tsx  ── act(fn) ──►  store  ──► re-render      │
│        │                                                    │
│        ├── fx({...}) ──────────► three (RetroEngine, сцены) │
│        └── sfx.xxx() ──────────► audio (WebAudio-синт)      │
└─────────────────────────────────────────────────────────────┘
┌──────────────── Домен (чистый TypeScript) ──────────────────┐
│ core/store.ts   zustand + persist + undo/redo (снимки)       │
│ core/session.ts хелперы над драфтом                          │
│ core/shrine.ts  экономика алтаря                             │
│ games/*/logic.ts движки игр (GameLogic)                      │
│ core/perks + games/*/perks.ts контент перков                 │
└─────────────────────────────────────────────────────────────┘
```

### Поток данных

1. Игрок жмёт кнопку на доске → `act((draft) => addDart(draft, {n: 20, m: 3}))`.
2. `act` прогоняет мутацию через immer, кладёт старую сессию в `past` (undo), сохраняет в localStorage.
3. Доска сравнивает состояние до/после (например, длину `history`) и стреляет эффектами:
   `fx({ type: 'darts.hit', … })`, `sfx.dart()`, баннер `announce('180')`.
4. Хук `useSessionFx` в `Play` ловит изменения душ и конец партии → искры душ, монетки, фанфары.

### Сессия

`Session` — единственный источник правды партии: игроки (души, перки, статистика), `game` (состояние конкретной
игры), журнал, RNG-состояние, счётчик ходов, открытый пакт. Сериализуется целиком (persist + undo-снимки).

RNG — mulberry32 с состоянием в сессии: undo откатывает и случайность, тесты детерминированы.

### Перки

`PerkDef` (контент) → `ActivePerk` (экземпляр у игрока: uid, заряды/тики, параметры, кто наслал).
Эффекты-теги читаются логикой игры через `effects(player, tag)` / `spendEffect(...)`.
Тики: игра вызывает `tickPerks(s, ids, unit)` в конце хода/раунда/розыгрыша. Единица `turn` у общих перков
автоматически маппится на «родную» единицу игры (`GAME_TICK_UNIT`).

### Рендер

`RetroEngine` держит один WebGL-контекст на всё приложение. Сцены (`BaseScene`) создаются по требованию и
уничтожаются при уходе (текстуры процедурные и кешируются глобально). Переход = дизер-растворение → swap → intro.
FX-события, пришедшие во время перехода, ставятся в очередь (`whenReady`).
`setFrame(x, y)` сдвигает проекцию, чтобы герой сцены был в свободной от UI области.

Обратный канал «мир → UI»: `Play` пересылает тапы по пустой части экрана в `pointerToScene`, сцена делает
raycast и шлёт `SceneEvent` (`chess.square`, `darts.board`, `darts.aim`…), UI подписан через `onScene`.
После каждой смены сцены движок шлёт `scene.ready` — доска игры по нему заново отправляет состояние
(`chess.sync`, `darts.score`, часы), потому что новая сцена строится с нуля. В URL `?debug` движок
доступен как `window.__engine` — для Playwright-скриптов (проекция клеток/секторов в экранные координаты).

## Как добавить игру (чек-лист)

1. `src/core/types.ts` → добавить id в `GameId`.
2. `src/games/<id>/state.ts` — интерфейс состояния.
3. `src/games/<id>/logic.ts` — `GameLogic`: `createGame`, `currentPlayerId`, `standings`, `scoreView`,
   `shrineAccess`, `status`, опционально `applyInstant`, `onResume`, `beforeShrine`.
   Все действия — функции `(draft: Session, …) => void`; доход — через `awardSouls`, тики — `tickPerks`,
   конец — `finish(s, standings)`.
4. `src/games/<id>/perks.ts` — 8–12 даров и 6–10 проклятий (обычные/редкие/эпик, 1 легенда).
5. `src/games/<id>/Board.tsx` — пульт: кнопки → `act()` → `fx()` + `sfx`.
6. Зарегистрировать: `games/logic.ts`, `games/boards.ts`, `games/meta.ts` (+`GAME_ORDER`), `core/perks/registry.ts`
   (`ALL_PERKS`, `GAME_TICK_UNIT`).
7. 3D: сцена в `three/scenes/<world>.ts` (наследник `BaseScene`), фабрика в `three/index.ts`, тотем в `hub.ts`
   (`HUB_ORDER` в том же порядке, что `GAME_ORDER`), новый `SceneId` в `three/fx.ts`.
8. Звук: дрон мира в `DRONES` (`audio/sfx.ts`).
9. Тесты в `src/__tests__/games.test.ts`: подсчёт очков, доход, конец партии, авто-перки.

## Тесты

`npm test` — vitest в node-окружении. Покрыты: X01 (переборы, дабл-аут, щит, множители, чекауты), доход дартса,
фора, шансы колеса (нормировка, место, милость, хаос, эмпирическое распределение), пакт (уникальность, гарантия
редкого), сглаз (цена, оберег, зеркало), доход/налог, слоты, дурак (маска, двойной позор, лимит), пинг-понг
(подача, больше-меньше, двойное очко, стена), шахматы (часы, инкремент, скорость, месть; стол: мат, рокировка,
взятие на проходе, проклятия-фильтры, перк-ходы), универсальная игра.

Визуал проверяется Playwright-скриншотами (Chromium + SwiftShader) — см. историю PR.

## Хранение

`localStorage['rlge-save-v1']`: ростер, последние сетапы по играм, настройки, текущая сессия, летопись (40 партий).
Undo-история в памяти (60 шагов). Миграции: при смене схемы — поднять версию ключа и написать `migrate` в persist.
